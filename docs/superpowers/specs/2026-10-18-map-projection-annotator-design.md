# 地図投影を主とした経路ラベル アノテータ 設計

日付: 2026-10-18
対象リポジトリ: `tools/path_annotator`（aif_path_annotator）
対象データ: `/home/kyo/aif_dataset/20261012_data`（1,580 フレーム）を最初の適用先とする。他の bag でも同じ形式なら使える。

## 1. 意図と背景

現状の経路ラベル（`labels/<split>/<frame>.txt`、48 行の `xp` / `h_vector` / `class`）は、
GNSS 軌跡を vectormap の中心線へ一括で剛体合わせ込みし、各フレームで中心線をカメラへ投影して自動生成されている。
20261012 の bag は合わせ込み残差が 0.71 m と大きく、経路が白線や隣レーンへずれるフレームが目立つ。

既存の path_annotator は「人が制御点を打って曲線を直す」ことを主としていた。人が点を打つと
行ごとのぶれ、フレーム間の不整合、レーン幅との不一致が起きやすく、品質の担保が難しい。

本設計では主役を入れ替える。**ラベルは常に「フレームごとの車両姿勢」から vectormap を投影して生成し、
人は姿勢を確認・修正するだけ**にする。姿勢が正しければ、経路は地図の中心線どおりの滑らかで一貫した形になる。

## 2. ゴール / 非ゴール / アンチゴール

### ゴール

- 各フレームで、画像上に地図（観測可能な白線とレーン中心線の straight / left / right）を投影して重ね、
  YOLOP の白線検出マスクと照合コストで「どの程度一致しているか」を目で見て判断できる。
- 車両姿勢（横・前後・ヨー、必要ならカメラピッチ）を、俯瞰パネルのドラッグとキー操作で微調整できる。
- 自動照合の複数候補を並べて表示し、1 クリック（またはキー 1 つ）で選べる。
- bag の時系列順に進み、前フレームで確定した姿勢を次の初期値にして自動照合し、Enter で確定して次へ進める。
  ずれたフレームだけ人が介入する。
- 確定時に既存形式のラベルを書き、姿勢も別ファイルに保存する。left / right も地図から投影する。
- 要確認フレーム（照合コストが悪い、前フレームからの姿勢の飛びが大きい、経路が取れない）に印を付け、
  あとでそれだけを回れる。

### 非ゴール

- 制御点を手で打つ・ドラッグする編集機能は提供しない（旧ツールの add / delete モード、補間、伝播、曲線再生成）。
- 学習済み経路ネットワークによる推論ラベル（旧 `--weights` / `infer.py`、乖離順キュー）は本ツールから外す。
  必要になれば git 履歴（コミット 3b6ee43）から戻せる。
- vectormap や gnss.json の生成・修正はしない（入力として使う）。
- GPU 前提にしない。CPU のみで実用速度を出す。

### アンチゴール（技術的には動いても失敗とみなす状態）

- 隣のレーンに乗った滑らかなラベルが「良好」として確定される（レーン幅周期の誤照合）。
- Enter を押すたびに数秒待たされ、1 枚ずつ進む流れが成り立たない。
- 学習側が読めないラベル（straight 欠落、class 重複、48 行でない、範囲外の値）が書かれる。
- 投影の計算をツール内で独自実装し、学習側の `converter.py` と結果がずれる。

- 入力の必須ファイル: `images/<split>/*.png`（640×384、nHD をレターボックス）、`labels/<split>/*.txt`（初期ラベル。無くても動くのが望ましいが、

- 起動引数は現行の `--root` / `--vectormap` / `--yolop` / `--params` / `--learning-repo` / `--port` / `--no-browser` を踏襲し、
  `--vectormap` 系を必須にする（本ツールは地図投影が前提）。`--weights` / `--branch-threshold` は廃止。

  保存前検証（`store.validate_label`）は現行のまま使う。
- 標準ライブラリの HTTP サーバ（`127.0.0.1` のみ）とフロントは素の JS、という現行の構成を維持する。
- 既知の事実（2026-10-18 計測）: `gnss.json` の `yaw_imu_rad` は走行中の `yaw_motion_rad` に対し中央値 +10.5° の偏りがある。
  照合コスト（検出点から最寄り地図線までの平均距離、0.5 m で打ち切り）の床は 0.27 m 付近で、
  しきい値 0.25 m は多くのフレームでぎりぎり超える。レーン幅 3.3 m ごとに似たコストの局所解がある。
- 速度の実測（この PC の CPU、現行 `bev_match`、地図線 5,511 点、白線 800 点）: 広い窓 2.3 秒、狭い窓 1.1 秒。
  候補 4 件を現行実装のまま照合すると 1 フレーム 5〜9 秒かかるので、照合の実装は 5.2 のとおり作り直す。
- 速度の予算: マスクがキャッシュ済みなら Enter から次フレームの表示（既定姿勢と候補 4 件を含む）まで **1 秒以内**。
  キャッシュが無いフレームは YOLOP の 2.5 秒が乗るのを許容する。
- 20261012_data は bag が 1 本で、時系列で見ると train と val が交互に並ぶ（train 309 → val 156 → train 633 → …）。
  時系列キューと姿勢の引き継ぎは split をまたいで扱う（5.5）。
- `main_params.yaml` のカメラ姿勢は rpy = (−89.80, 0.50, −89.64) で、`rotation_from_rpy`（Rz·Ry·Rx）の規約では
  yaml の `pitch` は光軸まわりの回転であり、物理的なチルト（水平線が上下に動く回転）は yaml の `roll` に相当する。
  本設計で言う「ピッチ」は物理的なチルトのことで、yaml の値に足すのではなく 5.1 の方法で与える。

- 操作性は **案 C（俯瞰パネルでドラッグ）** を基本にし、**案 D（候補から選ぶ）** も持つ。
- 進め方は **W2（時系列で前フレームの姿勢を引き継ぎ、Enter で確定）**。
- left / right も地図から投影する。
- 画面構成は **レイアウト A**: 画像を主役に、右に俯瞰パネルと数値、下に候補の横並び。
- 人が点を打つ機能は主経路から外す。
- 画像への地図投影の重ね表示は **半透明** にし、不透明度を **スライダーで調整** できるようにする
  （不透明な太線で白線が塗りつぶされ、一致しているか見えなくなるのを避ける）。

## 5. 設計

### 5.1 データモデル

**姿勢（pose）** はフレームごとに次を持つ。

| 項目 | 意味 |
|---|---|
| `x`, `y` | vectormap 座標系の車両位置 [m] |
| `yaw` | 進行方向 [rad] |
| `pitch` | カメラの物理的なチルトの補正量 [deg]、既定 0。正の値で水平線が画像の上へ動く（カメラが下を向く）向きに統一する |
| `source` | `gnss` / `auto` / `candidate` / `manual` / `propagated` のいずれか。最後に姿勢を決めた手段 |
| `cost` | その姿勢での照合コスト [m]。白線点が少なくて計算できないときは null |
| `flags` | `cost`（しきい値超え）、`jump`（初期値からの差が大きい）、`no_path`（straight が取れない）、`few_points`（白線点不足）の部分集合 |
| `ts` | 更新時刻 |

保存先は `<root>/poses.json`（`{"frames": {"<split>/<name>": pose}}`）。原子的に書く（現行 `_atomic_write_json` を流用）。
確定状態（`unseen` / `done` / `skip`）は現行の `annotation_state.json` を引き続き使う。

**ラベル** は確定（Enter）時にのみ、その時点の姿勢から生成して `labels/<split>/<name>.txt` に書く。
生成は `trace_paths(vector_map, position, yaw, horizon=20)` で得た `straight` / `left` / `right` の各折れ線を
0.2 m 間隔に再サンプリングし、車両座標へ変換してカメラへ投影し、`row_anchor_columns` で 48 行にする（現行 `label_from_pose` と同じ手順を
全クラスに拡張する）。有効行が 1 つも無いクラスは出力しない。straight が無ければ保存できない（`no_path`）。

**白線検出マスクのキャッシュ**: `<root>/cache/yolop/<split>/<name>.png`（0/255 の 1 チャネル PNG）。
一度計算したフレームは二度と YOLOP を走らせない。

**ピッチの実装**: カメラモデルは学習リポジトリの `load_camera` で作った `CameraModel` をそのまま使い、
ピッチが 0 でないフレームでは、その `rotation` に車両の左右軸（base の Y 軸）まわりの回転を合成した `CameraModel` を作って投影する
（射影そのものは再実装しない。回転の合成順は「+1° で水平線が約 4.4 px 上へ動く」ことをテストで確かめて決める）。
YOLOP 点の俯瞰変換に使う行→距離の表（現行は起動時に 1 回作る）も、そのフレームのピッチで作り直す（0.1° 刻みで丸めてキャッシュ）。
これにより、ピッチを動かすと画像の重ね・俯瞰の点群・照合コストの三つがそろって追随する。
ピッチが 0 でない姿勢には flag `pitch` を付ける（`converter.py` では再現できない投影なので、あとから見分けられるようにする）。
ピッチは実装順を最後にしてよく、無くてもツールとして成立する。

**skip したフレームの扱い**: skip は `annotation_state.json` の status だけを変え、ラベルファイルは触らない。
学習から外すには、別スクリプト `exclude_skipped.py --root <root>` で skip のフレームの画像とラベルを `<root>/excluded/<split>/` へ移す
（元に戻せるよう移動にする。実行は利用者が明示的に行う）。

### 5.2 姿勢の初期値と自動照合

- **ヨーの偏り補正**: bag ごとに、移動中（隣接フレーム間の速度 > 0.5 m/s）のフレームで
  `median(yaw_motion_rad - yaw_imu_rad)` を求め、GNSS 由来の初期ヨーは `yaw_imu_rad + bias` とする
  （停止中は `yaw_motion_rad` が不安定なので、IMU + 偏り補正に統一する）。
- **初期値の優先順位**（フレームを開いたとき、poses.json に姿勢が無い場合）:
  1. 時系列で直前の確定済みフレーム（同じ bag、`image_index` の差が 4 以内）があれば **引き継ぎ**:
     `position = prev.position + (gnss_now.xy - gnss_prev.xy)`、`yaw = prev.yaw + (yaw_imu_now - yaw_imu_prev)`、`pitch = prev.pitch`。
     その後 **狭い窓** で自動照合する。
  2. 無ければ GNSS の姿勢（偏り補正済みヨー）を初期値にし、**広い窓** で自動照合する。
- **照合**: 現行 `bev_match`（格子探索 + 細密探索）と同じ探索を、窓の幅を引数で変えられるようにして使う。
  - 狭い窓: 横 ±0.5 m（0.05 刻み）、前後 ±0.5 m（0.1 刻み）、ヨー ±3°（0.5° 刻み）。
  - 広い窓: 横 ±1.5 m（0.1 刻み）、前後 ±1.5 m（0.25 刻み）、ヨー ±8°（1° 刻み）。現行と同じ。
- **照合の実装（速度のため作り直す）**: 地図の観測可能な線から、地図の外接矩形（余白 5 m）を 5 cm 格子で覆う
  **距離場**（各セルから最寄りの地図線までの距離、0.5 m で打ち切り）を起動時に 1 回作る（約 3M セルの float32、`scipy.ndimage.distance_transform_edt` で作れる）。
  コストは白線点を仮説ごとに地図座標へ変換し、距離場を双一次補間で引いた平均にする。
  全仮説を numpy でまとめて評価し、広い窓で 0.3 秒以内、候補 4 件の合計で 1 秒以内を目標にする。
  コストの定義（最寄り地図線までの平均距離、0.5 m 打ち切り）は現行と同じで、格子の量子化による差は 3 cm 以内に収める。
  しきい値の既定は 0.25 m のまま。
- 先読みスレッドの YOLOP は `torch.set_num_threads(CPU 数の半分)` にし、照合と画面操作の CPU を残す。
- **候補（案 D）**: 初期値の集合 { 引き継ぎ姿勢、GNSS 姿勢、引き継ぎ姿勢を横に ±3.3 m ずらしたもの } からそれぞれ照合し、
  位置 0.4 m・ヨー 2° 以内のものを同一とみなして間引き、コスト昇順に最大 4 件を返す。引き継ぎ姿勢が無いときは GNSS 姿勢を起点にする。
  先頭候補が既定の姿勢になる。ただし引き継ぎがある場合は、引き継ぎ由来の候補とコスト最小の候補の差が 0.03 m 未満なら引き継ぎ由来を既定にする
  （レーン飛びの抑止）。
- **白線点が 30 点未満** のフレームは照合せず、初期値をそのまま姿勢にして `few_points` を付ける。
- **要確認フラグ**: `cost > しきい値（既定 0.25 m、`--cost-threshold` で変更可）`、
  `jump`（引き継ぎ初期値からの差が横 0.3 m またはヨー 2° を超える）、`no_path`、`few_points`。

### 5.3 サーバ API（標準ライブラリ HTTP、JSON）

すべての投影・照合・ラベル生成はサーバ側（Python）で行い、ブラウザは幾何（画素座標の折れ線、車両座標の点群）を受け取って描画する。
投影の正本を Python 側に一本化するため、JS 側では射影計算をしない。

| メソッド | パス | 役割 |
|---|---|---|
| GET | `/api/queue?order=time&status=&flag=` | フレーム一覧。`order=time` は bag ごとに `image_index` 順。`flag` で要確認だけに絞れる。各要素に status・flags・cost を含む |
| GET | `/api/frame/<split>/<name>` | フレームの姿勢（無ければ 5.2 の手順で初期化・照合して poses.json に書く）、`overlay`、`bev`、`cost`、`flags`、`candidates`、`prev` / `next`（時系列）、マスクキャッシュの進捗 |
| POST | `/api/preview` `{split, name, pose}` | その姿勢での `overlay`、`bev`、`cost`、`label` を返す。保存しない。ドラッグ中に高頻度で呼ぶので 50 ms 以内を目標 |
| POST | `/api/match` `{split, name, pose, window}` | 与えた姿勢を初期値に照合し、姿勢と候補を返す。保存しない（`r` キーの再探索用） |
| POST | `/api/pose` `{split, name, pose}` | 姿勢を poses.json に保存する（確定ではない）。フレーム移動時に呼ぶ |
| POST | `/api/confirm` `{split, name, pose}` | 姿勢からラベルを生成・検証して保存し、poses.json と status=done を更新する。straight が無い、または下記の棄却基準に当たれば 400 で理由を返す |

確定時の棄却基準は学習側 `Models/data_parsing/rosbag/converter.py` の `rejection_reasons` と同じにする:
最大の可視行数が 10 行未満、または straight の可視行の 50% 以上が画像端（`xp` < 0.02 または > 0.98）。
しきい値は converter から import できればそれを使い、できなければ同じ値をコピーして出典をコメントに書く。
棄却されたフレームは画面に理由を出し、姿勢を直すか `s` で skip にする。
| POST | `/api/status` `{split, name, status}` | `skip` / `unseen` の設定（現行） |
| GET | `/api/image/<split>/<name>` | 画像 PNG（現行） |
| GET | `/api/mask/<split>/<name>` | YOLOP マスク PNG（キャッシュから。無ければその場で計算して保存） |

`overlay` の中身: `lines`（地図の観測可能白線を画像へ投影した折れ線の配列。車両前方 0.8〜45 m、画像外は切る）、
`paths`（class ごとの中心線の折れ線）、`rows`（class ごとの 48 行 `xp` / `h_vector`。保存されるラベルそのもの）。
`bev` の中身: `lines`（車両座標の地図線、前方 -4〜28 m・横 ±13 m）、`paths`、`points`（YOLOP の俯瞰点群）。

### 5.4 画面（レイアウト A）とふるまい

```
+---------------------------------------------------------------+
| frame id | 1,021 / 1,580 | 時系列 | 照合 0.20 m 良好 | flags | cache 1,300/1,580
+-------------------------------------+-------------------------+
|                                     | 俯瞰パネル 300×360       |
|  画像 640×384（ウィンドウに応じて拡大） |  車両固定・前方が上        |
|  重ね: マスク(g) 地図線(m) 経路+行の点 |  地図線・経路・検出点群     |
|                                     +-------------------------+
|                                     | 補正 横/前後/ヨー/ピッチ   |
|                                     | コスト 初期→現在          |
|                                     | 行数 straight/left/right  |
|                                     | 初期値の出どころ          |
|                                     | 投影の不透明度 [=====   ]  |
|                                     | 検出の不透明度 [===     ]  |
+-------------------------------------+-------------------------+
| 候補 1: 0.20 | 候補 2: 0.21 | 候補 3: 0.31 | 候補 4: 0.33 |（サムネイルに経路と地図線を重ねる）
+---------------------------------------------------------------+
| キー一覧（1 行）                                                 |
+---------------------------------------------------------------+
```

- **画像**: `<canvas>`。画像の上に、マスク（緑、`g` で切替）、地図線（水色、`m` で切替）、経路（straight 黄・left 桃・right 橙）、
  保存される 48 行の点（経路と同色の小円）を描く。
  - **地図投影（地図線・経路・行の点）は半透明で描く**。不透明度は右列のスライダー（0〜100%、既定 50%）で変えられ、
    `[` / `]` でも 10% ずつ変えられる。設定はブラウザの localStorage に覚える。
  - 検出マスクの不透明度も別のスライダー（既定 35%）で変えられる。
  - 線の太さは地図線 2 px、経路 3 px を既定にし、画像の拡大率に合わせてスケールしない（拡大しても白線を覆わない）。
  - `o` を押している間は重ね表示をすべて消し、素の画像だけを見られる（離すと戻る）。
- **俯瞰パネル**: `<canvas>`。車両を下中央の白三角、前方を上、12 px/m（`+` / `-` で 8〜24 px/m）。地図線（水色）、経路（同色）、検出点群（緑）。
  - ドラッグ: 地図（線と経路）が動き、車両と点群は動かない。ドラッグ量を m に換算して横・前後の補正にする（ドラッグ中は 30 回/秒程度に間引いて `/api/preview`）。
  - ホイール: 車両を中心にヨーを 0.5°/ノッチ回す。
- **候補の列**: 最大 4 枚。各サムネイルは画像の縮小に、その候補の経路と地図線を描いたもの（クライアント側で描く。サーバは候補ごとの `overlay` を返す）。
  コストと補正量を角に表示。クリックまたは `1`〜`4` で姿勢を置き換える。選択中は枠を強調。
- **上部バー**: フレーム名、通し番号 / 総数、キュー種別、コストのバッジ（しきい値以下は緑、超えると橙で「要確認」）、flags、マスクキャッシュの進捗。
- **数値パネル**: 初期値からの補正量（横・前後・ヨー・ピッチ）、コスト（初期値 → 現在）、class ごとの有効行数、初期値の出どころ。

キー操作:

| キー | 動作 |
|---|---|
| `Enter` | 確定して次のフレーム（時系列）へ |
| `←` `→` | 確定せずに前 / 次のフレームへ（現在の姿勢は `/api/pose` で保存） |
| `h` `l` / `j` `k` / `u` `i` | 横 ±0.05 m / 前後 ±0.10 m / ヨー ±0.5°。`Shift` で 5 倍 |
| `,` `.` | ピッチ ±0.2°（`Shift` で 5 倍） |
| `1`〜`4` | 候補を選ぶ |
| `r` | 現在の姿勢を初期値に広い窓で再探索し、候補を作り直す |
| `Esc` | 初期値（引き継ぎまたは GNSS）に戻す |
| `z` / `Shift+z` | フレーム内の undo / redo（姿勢の履歴） |
| `g` / `m` | マスク / 地図線の表示切替 |
| `[` `]` | 地図投影の不透明度を 10% ずつ下げる / 上げる |
| `o`（押している間） | 重ね表示をすべて消して素の画像を見る |
| `s` | skip にして次へ |
| `f` | 要確認だけのキューに切替 / 戻す |
| `+` `-` | 俯瞰の縮尺 |

### 5.5 進め方 W2 の流れ

1. 起動時、キューは時系列（bag → `image_index`）。**split は混ぜる**（train と val が時間で交互に並ぶので、split ごとに分けると引き継ぎが切れる）。
   `prev` / `next` は split 付きで返す。引き継ぎ（`image_index` の差 4 以内）も split をまたいでよい。最初の未確定フレームを開く。
2. サーバは起動直後からバックグラウンドのスレッド 1 本で、現在のフレームから時系列順にマスクをキャッシュへ先読みする
   （現在フレームが要求されたら、そのフレームを最優先にする）。上部バーに進捗を出す。
   キャッシュが先行していれば Enter 後の表示は照合（0.5 秒未満）だけで済む。
3. フレーム表示時、poses.json に姿勢があればそれを使う。無ければ 5.2 の初期化と照合を行い、結果を poses.json に書く（`source` は `auto` または `propagated`）。
4. 人は画像と俯瞰で一致を見る。問題なければ Enter。ずれていれば候補を選ぶか、俯瞰のドラッグ・キーで直してから Enter。
   `source` は候補選択で `candidate`、手動調整で `manual` になる。
5. Enter でラベルと姿勢を保存し、次のフレームへ。次のフレームの初期値はいま確定した姿勢を引き継ぐ。
6. あとから `f` で要確認フレームだけを巡回し、直す。

## 7. 設計者の判断（利用者が明示していない点）

- ラベル形式は維持し、姿勢は `poses.json` に別保存する。
- `--weights` と推論ラベル機能は外す。
- カメラピッチは姿勢の 4 つ目の自由度として持つ（既定 0、キーで調整、引き継ぎ時はコピー）。物理的なチルトとして実装し、俯瞰とコストも追随させる。実装順は最後。
- 初期ヨーは `yaw_imu_rad` に bag ごとの偏り補正を足したものにする。
- 引き継ぎ時の照合窓は狭くし（横 ±0.5 m、ヨー ±3°）、レーン飛びは候補（±3.3 m）で拾う。
- 照合は距離場（5 cm 格子）で高速化する。コストの定義は変えず、量子化誤差は 3 cm 以内。Enter から次の表示まで 1 秒以内を予算にする。
- straight が取れないフレーム、および converter.py の棄却基準（可視行 10 行未満、画像端 50% 以上）に当たるフレームは確定できず、直すか skip にする。
- skip はラベルを消さない。学習から外すのは別スクリプト（`exclude_skipped.py`）で明示的に行う。
- 時系列キューと引き継ぎは train / val をまたぐ。
- マスクはディスクにキャッシュし、バックグラウンドで時系列順に先読みする。
- 投影計算はサーバ側に一本化し、JS は描画のみ。
